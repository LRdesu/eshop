
## 4. 关键业务规则（防坑定义）

### 4.1 优惠券叠加互斥规则（用户点名最易出 bug 处）
**采用确定性、可推导的规则，杜绝组合歧义：**

| 券类型 | 维度 | 互斥规则 |
|--------|------|----------|
| `FULL` 满减券 | 商品 | 一个订单**最多 1 张** |
| `DISCOUNT` 折扣券 | 商品 | 与 `FULL` **互斥**，二者取其一；同类最多 1 张 |
| `SHIPPING` 运费券 | 运费 | 一个订单**最多 1 张**，且**可与上述商品券叠加** |

即：**商品维度 ≤ 1 张 + 运费维度 ≤ 1 张**，跨维度可叠加，同维度绝不叠加。
券可用性还须同时通过：有效期、使用门槛（满 X 减 Y）、适用范围（全场/分类/指定商品）、持有且未使用。
**前后端同规则校验**：前端据此置灰不可选券，后端再校验一次（不信前端）。

### 4.2 优惠分摊算法（决定退款金额）
```
订单优惠额 discount 分摊到各行：
  item.discount = round(order_discount * item.goods_amount / Σgoods_amount, 2)
  尾差（几分钱）补到金额最大的那一行，保证 Σitem.discount == order.discount
```
使用 `Decimal` 计算，**绝不使用 float**。

### 4.3 退款口径（用户点名重点）
```
退款金额 = round(item.pay_amount / item.quantity * refund_qty, 2)
```
**按实付分摊比例退，绝非按原价 `goods_amount` 退。**
- 部分退款：不退运费
- 全部退款且使用了运费券：运费券失效，运费一并退
- 退款成功后**回补库存** `sku.stock += qty`

### 4.4 支付幂等与超时关单
- 支付单 `payment_no` 唯一；**幂等键 = payment_no + 目标状态**
- 重复 SUCCESS 回调：直接返回成功，**不重复加积分 / 不重复扣款 / 不重复发货**
- 已 SUCCESS 后再收到失败回调：**忽略**，状态不可回退
- 超时关单：查询订单/支付单时**惰性检查** `expire_at < now 且未支付` → 关单 + 释放库存 + 券状态回滚（`CLOSED`）

### 4.5 履约与自动收货
- 商家发货 → 生成 `shipments` + 运单号 → 写 `shipment_traces` 轨迹（已揽收/运输中/派送/签收）
- 签收后进入待确认，超过自动确认时限 → 查询惰性触发 `order_status=4 已完成`

### 4.6 RFM 分层
- **R** 最近一次下单距今天数 / **F** 累计订单数 / **M** 累计实付金额
- 分层标签写入 `user_tags`：如 `重要价值客户` / `重要保持客户` / `一般发展` / `流失挽留` / `新客`

## 7. 物流系统设计（v0.3 新增）

### 7.1 地理约定（演示口径）

| 项 | 约定 |
|----|------|
| 发货仓库 | 统一「上海中心仓」，`shipments.from_city = 上海` |
| 收货地址 | 统一「江苏 / 南京」，`shipments.to_city = 南京`（由订单地址推导，缺省南京） |
| 运费判定 | `LOCAL_PROVINCE = 上海`（仓库所在省），南京 → 按省外运费计 |

### 7.2 物流状态机（`ship_status` 0~6）

```
0 待发货 → 1 已发货 → 2 仓库拣货 → 3 已揽收 → 4 运输中(上海→南京) → 5 派送中 → 6 已签收
```

- 「商家发货」动作：生成运单（状态 1），订单 `order_status → 2 已发货`
- 每推进一次产生该阶段的轨迹节点；「运输中」一步产生 **2 条轨迹**（离开上海 / 抵达南京），完整呈现跨城运输过程
- 签收（6）→ 订单 `order_status → 3 已签收`，此时开放售后入口；确认收货后 `order_status → 4 已完成`

### 7.3 轨迹数据（`shipment_traces` 新增 `city`）

轨迹明细示例（一条运单的完整生命周期）：

| 节点 | 城市 | 描述 |
|------|------|------|
| 已发货 | 上海 | 商家已发货，顺丰速运运单已生成，等待仓库处理 |
| 仓库拣货 | 上海 | 【上海中心仓】已完成拣货打包，等待快递揽收 |
| 已揽收 | 上海 | 【上海】顺丰速运已揽收 |
| 运输中 | 上海 | 快件已离开【上海转运中心】，发往【南京】 |
| 运输中 | 南京 | 快件已抵达【南京转运中心】 |
| 派送中 | 南京 | 【南京】快递员正在派送，请保持电话畅通 |
| 已签收 | 南京 | 【南京】快件已签收，感谢使用 |

### 7.4 前端订单详情页（`/order/:id`）

订单列表整卡可点击进入，单页聚合展示全链路：

1. **订单信息**：订单号 / 状态 / 金额明细（商品·优惠·运费·实付）/ 商品行 / 收货地址（南京）
2. **物流进度**：运单号、承运商、`上海 → 南京` 路由标识、el-timeline 轨迹（节点 + 城市标签 + 描述 + 时间）；
   操作按钮按状态出现：商家发货（演示）→ 推进物流 ×5 → 确认收货
3. **售后**：签收后展示申请表单（类型 / 商品 / 数量 / 原因）+ 本订单售后单列表与退款操作；
   退款按实付分摊比例计算，成功后回补库存、回退积分

## 8. 商家后台设计（2026-10-04 新增）

### 8.1 定位与接入方式

商家后台与买家端**共用同一个 FastAPI 服务与同一个 Vue3 站点**，通过路径与令牌双隔离共存：

| 维度 | 买家端 | 商家后台 |
| --- | --- | --- |
| 接口前缀 | `/api/v1/orders`、`/products` 等 | `/api/v1/admin/*` |
| 鉴权依赖 | `get_current_user` | `get_admin_user`（先登录，再校验 `role == 1`） |
| 前端令牌 | `localStorage.token` | `localStorage.admin_token`（独立 axios 实例 `src/api/admin.js`） |
| 前端路径 | `/`、`/orders`、`/cart` … | `/admin/login`、`/admin/*` |
| 布局 | `App.vue`（商城头部 + 分类导航） | `AdminLayout.vue`（左侧菜单 + 顶栏），`/admin` 下自动隐藏买家端导航与页脚 |

好处：同一浏览器可同时保持买家与商家两种登录态，互不覆盖。

### 8.2 身份模型

- `users` 表新增 `role SMALLINT NOT NULL DEFAULT 0`（0 买家 / 1 商家管理员），迁移脚本 `backend/migrate_admin.py`（幂等：列存在则跳过，账号存在则只修正 role）。
- 内置演示商家账号：**`admin` / `admin123`**。
- 买家账号登录商家后台会被拒绝（`该账号无商家后台权限`）。

### 8.3 功能模块与接口

| 模块 | 主要接口 | 能力 |
| --- | --- | --- |

## 10. 性能 / 健壮性 / 体验优化（v0.4 新增）

### 10.1 N+1 查询消除（性能）
原实现中，列表接口对每个订单/商品/售后逐行发 `db.get(Sku)`、`db.get(Product)`，列表查询量随数据量线性放大，是订单与商品列表的主要瓶颈。

| 位置 | 原写法 | 优化后 |
| --- | --- | --- |
| `order_service.to_resp` | 每个订单项各查一次 SKU、Product | 先收集 `sku_ids`/`prod_ids`，一次 `WHERE id IN (...)` 批量预取，内存分组 |
| `catalog_service.list_products` | 每件商品各查一次 SKU | 一次 `WHERE product_id IN (...)` 取全部 SKU 后按 `product_id` 分组 |
| `admin.aftersales` 列表 `_as_dict` | 每条售后各查一次 SKU、Product、Order | 列表端点先批量预取三表，按 id 映射后传入，避免逐条查询 |

> 说明：`to_resp` 对单个订单仍各查一次 `Shipment`（1 次/单），属 O(N) 而非 O(N×M)，无性能问题，故未做批量。

### 10.2 过期关单副作用移出读接口（健壮性）
原 `orders.preview` 与 `orders.list_orders`（均为 GET）会在每次浏览时调用 `payment_service.close_expired(db)` 扫描全表并 `commit`，读接口产生写副作用，且买家端与商家端行为不一致（商家订单列表不触发）。
- 现移除读接口中的 `close_expired` 调用；
- 改为在 `order_service.create_order`（写路径）开头触发，保证「下单前先释放过期未付订单占用的库存」这一业务语义不变，且只在写操作时发生。

### 10.3 CORS 收窄（安全）
`app.add_middleware(CORSMiddleware, allow_origins=["*"], allow_credentials=True)` 中 `*` 与凭据互斥，浏览器会拒绝带凭据的 `*`，当前仅因 Vite 代理同源才可用。改为具体开发源：`["http://127.0.0.1:5173", "http://localhost:5173"]`。

### 10.4 列表分页（体验）
买家订单列表 `/orders`、商家订单列表 `/admin/orders`、商家售后列表 `/admin/aftersales` 均新增 `page` / `page_size`（上限 100）参数，返回结构统一为：
```json
{ "items": [...], "total": 123, "page": 1, "page_size": 20 }
```
前端三处列表页（`OrderList.vue`、`AdminOrders.vue`、`AdminAfterSales.vue`）接 `el-pagination`，数据增长后不再一次性拉全量。

### 10.5 清理死代码（维护性）
- 删除 `shipment_service.auto_confirm`（从未被任何调用方触发，`auto_confirm_at` 字段写了却不生效）；
- 从 `Order` 模型移除 `auto_confirm_at` 列，并新增幂等迁移 `backend/migrate_drop_auto_confirm.py` 在线上库 `DROP COLUMN`；
- 同步移除 `advance` 中对 `auto_confirm_at` 的赋值与已无用的 `timedelta` / `config` 导入。
